# ATOMiK Competitive Positioning Memo

Internal alignment memo. Use public excerpts carefully and keep claim labels
attached.

## Category

State-aware compute infrastructure.

## Core Wedge

ATOMiK targets systems that waste too much work moving, replaying, rescanning,
or reconstructing state.

## Primary Alternatives

- Full-state replication
- Event replay / event sourcing
- CRDT-style software merge logic
- Custom one-off FPGA accelerators
- Conventional CPU/GPU/OS paths that treat state change as application logic

## What ATOMiK Is

- A state-aware execution architecture.
- A delta-first way to model state change.
- A proof-backed technical substrate with public software and hardware work.
- A potential path to evaluations, design partners, support, integration, and
  targeted licensing.

## What ATOMiK Is Not Claiming Publicly

- A general-purpose replacement for CPUs, GPUs, operating systems, or SaaS
  stacks.
- A shipped commercial desktop product.
- A production customer deployment without referenceable proof.
- Guaranteed workload savings.
- Live-board proof for synthesis-only ceilings.

## Strongest Public Framing

The competitor is the status quo behavior: moving unchanged state, replaying
history, rescanning memory, and coordinating state through increasingly complex
systems.

## Evidence Boundary

Use `LIVE_MEASURED`, `HARDWARE_VALIDATED`, `SOFTWARE_VALIDATED`,
`SYNTHESIS_VALIDATED`, `PROJECTED`, `CONCEPTUAL`, and `ROADMAP` labels wherever
claims could be misread.
