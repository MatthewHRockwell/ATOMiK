# ATOMiK 5-Minute Talk Track

Use this when the room is rushed. It is keyed to `ATOMiK_5_Minute_Deck.pdf`, not the full 16-slide investor deck.

| Time | Slide | Point |
|---:|---|---|
| 0:00-0:35 | 1 - Cover | ATOMiK makes change the unit of compute. We start with one constrained workload, one baseline, and one painful metric. |
| 0:35-1:15 | 2 - Customer pain | Batteries die too quickly, hardware is maxed out, systems run hot, devices get too big/heavy, costs rise, and more performance is needed. |
| 1:15-2:00 | 3 - Mechanism | ATOMiK keeps reference state plus accumulated change: LOAD, ACCUM, READ, SWAP. This is not a CPU replacement. |
| 2:00-3:05 | 4 - Proof | Proof is evidence-labeled: Zynq UI, Linux-to-FPGA path, AX7020 matrix with wins and losses, and SD boot build artifacts. No universal speedup or battery/heat claim. |
| 3:05-4:00 | 5 - Commercial path | They show us the constrained path; we evaluate fit; then show measured opportunity or call no-fit. Design partner/licensing comes after proof. |
| 4:00-4:45 | 6 - Ask | We are raising a $5M target pre-seed to reach measured workload proof, IP packet, ASIC feasibility, and the paid-evaluation/design-partner path. No tape-out funding. |
| 4:45-5:00 | Close | Bring one constrained state path, measure the waste, and decide with evidence whether state-aware compute belongs there. |

Hard guardrails:
- Treat revenue ranges as founder-prepared planning scenarios, not forecasts.
- Do not give a valuation cap in the room.
- Do not claim signed traction, booked revenue, guaranteed customer savings, production readiness, or funded tape-out.
- Keep battery, heat, water, cooling, and footprint as evaluation targets until measured.
