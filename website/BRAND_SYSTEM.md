# ATOMiK Brand System

## Brand Name

Use `ATOMiK` in plain text. Do not alternate between Atomik, ATOMIK, and ATOM i K in written copy.

## Logo Usage

Primary wordmark: ATOMiK.

Icon direction: atom orbit mark or circular delta-state node. The assistant concept visual is not the logo.

Special treatment: the `i` dot may be an amber node in designed lockups. Keep the `K` sharp and technical.

Avoid overusing atom symbols, making the identity look like a school science project, or using the assistant visual as the primary logo.

## Atom AI Assistant Usage

Use the assistant as a premium visual guide for the pitch opener, evaluation-process moments, and Q&A dividers.

Do not use the assistant on heavy proof slides, benchmark slides, legal/IP slides, or financial slides.

If the assistant appears as a UI/product guide, label it as conceptual unless and until it is a working commercial product.

Approved caption: `Concept visual used as a guided evaluation motif. It is not a claim that Atom AI is a current commercial assistant product.`

## Typography

Headlines: Space Grotesk, Sora, or a Neue Haas Grotesk-style equivalent.

Body: Inter.

Metrics and proof labels: IBM Plex Mono or JetBrains Mono.

## Proof Label Styling

Use uppercase proof stamps:

- LIVE_MEASURED
- HARDWARE_VALIDATED
- SOFTWARE_VALIDATED
- SYNTHESIS_VALIDATED
- BUILD_ARTIFACT
- PROJECTED
- CONCEPTUAL
- ROADMAP

Proof labels should be visually sober: mono type, 1px border, small uppercase, no hype language. Use evaluation target as explanatory copy, not as an evidence-label stamp.

## Slide Design Rules

Each main slide gets one headline, one main visual, one proof or business takeaway, and no more than 35-45 words unless it is an appendix slide.

Use large type. Do not bury important caveats in tiny footnotes. Move detailed caveats into appendix slides or proof cards.

## Website Design Rules

The homepage remains customer-first and evaluation-first. The `/pitch` route is a meeting route, not a replacement homepage.

Concept visuals must be labeled. Performance numbers must link to artifacts. Synthesis and roadmap materials must not be blended with live measured results.

## Visual Language

Use delta paths, state maps, proof cards, dark technical backgrounds, amber constraint lanes, cyan/violet state paths, and clean evidence labels.

Avoid generic neon, crypto-style visuals, dense academic diagrams on main slides, or mascot-heavy proof pages.
