## 1. 7-Series Clocking Architecture

Xilinx 7-Series devices (including the Zynq-7020 PL fabric) provide a rich clocking infrastructure. Four types of clock management and distribution primitives are available.

### 1.1 Clock Managers

| Primitive | Count (XC7Z020) | Outputs | Fractional Divide | Phase Shift | Duty Cycle Control | Dynamic Reconfig |
|-----------|:---------------:|:-------:|:------------------:|:-----------:|:------------------:|:----------------:|
| **MMCM** | 4 | 7 (CLKOUT0-6) | Yes (CLKOUT0 only) | Yes (fine + coarse) | Yes | Yes (DRP) |
| **PLL** | 2 | 6 (CLKOUT0-5) | No | Yes (coarse only) | No | Yes (DRP) |

**MMCM (Mixed-Mode Clock Manager)**: The most capable clock generator. Supports fractional divide on CLKOUT0 (e.g., divide by 2.5 or 3.125), fine phase shifting in increments of 1/56th of the VCO period, and per-output duty cycle control. Use MMCM when fractional frequencies or fine phase control are required.

**PLL (Phase-Locked Loop)**: Simpler, lower-jitter variant. Six outputs, integer-only divide, coarse phase shifting (multiples of 45 degrees). Use PLL when only integer frequency ratios are needed and lowest jitter matters.

**Key difference from Gowin**: The GW1NR-9 has exactly 2 rPLL units with 4 outputs each. The XC7Z020 has 4 MMCM + 2 PLL = **6 total clock generators** with up to 7 outputs each. The PLL bottleneck that is a hard limit on Gowin does not exist on Zynq.

### 1.2 Clock Buffers

| Buffer Type | Count (XC7Z020) | Reach | Typical Use |
|-------------|:---------------:|-------|-------------|
| **BUFG** | 32 | Global (entire device) | Primary clocks, high-fanout enables |
| **BUFH** | 12 (per region) | Horizontal (one clock region) | Regional clocks, clock domain isolation |
| **BUFR** | 4 (per I/O column) | Regional (one I/O bank) | I/O-adjacent clocking, source-synchronous |
| **BUFIO** | 4 (per I/O bank) | I/O only (no fabric access) | High-speed I/O clocking (SERDES, LVDS) |
| **BUFMR** | 4 (per I/O column) | Multi-region | Bridge BUFIO/BUFR across adjacent regions |

**BUFG** is the workhorse. Every clock that drives fabric logic must go through a BUFG (or BUFH for regional clocks). With 32 BUFG available, clock buffer exhaustion is extremely unlikely.

### 1.3 PS-to-PL Clocks (Zynq-Specific)

The Zynq PS (Processing System) provides up to 4 fabric clocks:

| PS Clock | Configurable Range | Default | Drives |
|----------|:------------------:|:-------:|--------|
| FCLK_CLK0 | 10-250 MHz | 100 MHz (Vivado default) | AXI GP ports, general PL logic |
| FCLK_CLK1 | 10-250 MHz | disabled | Additional PL domain |
| FCLK_CLK2 | 10-250 MHz | disabled | Additional PL domain |
| FCLK_CLK3 | 10-250 MHz | disabled | Additional PL domain |

These are generated by the PS clock subsystem (ARM PLL, DDR PLL, IO PLL) and delivered to the PL via dedicated routing. They do NOT consume MMCM or PLL resources. Each FCLK can be independently configured in the Vivado PS configuration GUI.

**Typical Zynq ATOMiK setup**: Use FCLK_CLK0 at 50 or 100 MHz for AXI bus clock, then use one MMCM to generate the ATOMiK clock at a higher frequency.

| Parameter | Min | Max | Unit | Notes |

| **f_CLKOUT** | 4.69 | 800 | MHz | Output clock frequency |

| Speed Grade | f_VCO Min (MHz) | f_VCO Max (MHz) |

| -1 | 600 | 1200 |

| -3 | 600 | 1440 |

The CMOD A7 and PYNQ-Z2 boards typically use -1 or -2 speed grades. The VCO range is the same for -1 and -2; -3 extends the upper bound.

## 3. Frequency Calculation

### MMCM

```
f_VCO = f_CLKIN * M / D          (must be 600-1200 MHz for -2 speed grade)
f_OUT = f_VCO / O                (per output, each output has independent O)
```

Where:
- **f_CLKIN**: Input clock (e.g., 50 MHz from PS FCLK_CLK0)
- **M**: CLKFBOUT_MULT_F (feedback multiplier, fractional for MMCM)
- **D**: DIVCLK_DIVIDE (input divider, integer)
- **O**: CLKOUTn_DIVIDE (output divider, integer; CLKOUT0 supports fractional)

### PLL

Same formula, but M and O are integer-only:

```
f_VCO = f_CLKIN * M / D          (must be 800-1600 MHz)
f_OUT = f_VCO / O
```

### Verification Checklist

1. Compute f_VCO = f_CLKIN * M / D
2. Verify 600 <= f_VCO <= 1200 (MMCM, -2) or 800 <= f_VCO <= 1600 (PLL)
3. Compute f_PFD = f_CLKIN / D
4. Verify 10 <= f_PFD <= 450 (MMCM) or 19 <= f_PFD <= 450 (PLL)
5. Compute f_OUT = f_VCO / O for each output
6. Verify 4.69 <= f_OUT <= 800 (MMCM) or 6.25 <= f_OUT <= 800 (PLL)

| Target | M | D | O | f_VCO (MHz) | Actual (MHz) | Note |
|-------:|--:|--:|--:|:-----------:|:------------:|------|
| 100 | 20 | 1 | 10 | 1000 | 100.000 | Conservative start |
| 150 | 24 | 1 | 8 | 1200 | 150.000 | Mid-range |
| 200 | 20 | 1 | 5 | 1000 | 200.000 | Aggressive target |
| 250 | 20 | 1 | 4 | 1000 | 250.000 | Stretch goal |
| 300 | 24 | 1 | 4 | 1200 | 300.000 | Artix-7 theoretical limit |

**Context**: Gowin GW1NR-9 ATOMiK achieves Fmax ~100 MHz (target 81 MHz in production). The Artix-7 fabric in XC7Z020 is fabricated on 28nm vs Gowin's 55nm, providing significantly faster logic. Actual Fmax depends on synthesis results and is not guaranteed until Vivado P&R completes.

**Recommendation**: If ATOMiK is run at the same frequency as the AXI bus (100 MHz), no MMCM is needed and no CDC bridge is required. This is the simplest bringup path (Phase 1).

## 5. Gowin rPLL vs Xilinx MMCM Comparison

| Feature | Gowin rPLL (GW1NR-9) | Xilinx MMCM (XC7Z020) | Advantage |
|---------|:---------------------:|:----------------------:|:---------:|
| **Count** | 2 | 4 MMCM + 2 PLL = 6 | **Xilinx 3x** |
| **Outputs per unit** | 4 (CLKOUT, CLKOUTP, CLKOUTD, CLKOUTD3) | 7 (CLKOUT0-6) | **Xilinx** |
| **VCO range** | 400-1200 MHz | 600-1200 MHz (MMCM) | Similar |
| **Output range** | 3.125-600 MHz | 4.69-800 MHz | **Xilinx** |
| **Fractional divide** | No | Yes (CLKOUT0 only) | **Xilinx** |
| **Fine phase shift** | 4-bit (PSDA) | 1/56 VCO period steps | **Xilinx** |
| **Duty cycle control** | 4-bit (DUTYDA) | Per-output, 0.01% resolution | **Xilinx** |
| **Dynamic reconfig** | Yes (IDSEL, FBDSEL, ODSEL) | Yes (DRP port, 16-bit) | Both |
| **Input frequency** | 3-400 MHz | 10-800 MHz | Xilinx max higher |
| **Global clock buffers** | ~8 (shared routing) | 32 (BUFG) | **Xilinx 4x** |
| **PS-provided clocks** | N/A (no PS) | 4 (FCLK_CLK0-3, free) | **Xilinx** |

### Key Implications for ATOMiK

| Gowin Constraint | Zynq Resolution |
|------------------|-----------------|
| 2/2 PLLs used (HARD LIMIT) | 4 MMCM + 2 PLL + 4 FCLK = effectively unlimited |
| HDMI + ATOMiK consume all PLLs | Each gets its own MMCM with outputs to spare |
| New peripherals must derive from existing PLL | Dedicated MMCM or use FCLK_CLK1/2/3 |
| No fractional divide (awkward 27 MHz crystal ratios) | MMCM fractional on CLKOUT0 (e.g., 74.25 MHz for HDMI) |
| 8 clock buffer routes, contention possible | 32 BUFG, no contention |

**The PLL bottleneck is eliminated on Zynq.** This was the single hardest resource constraint on the GW1NR-9.

## 6. HDMI Clock Planning

If HDMI is driven from the PL fabric (rather than a dedicated HDMI IP or external encoder):

### 6.1 Required Frequencies

| Resolution | Pixel Clock | Serializer (5x pixel) | MMCM from 50 MHz |
|------------|:----------:|:---------------------:|-------------------|
| 720p60 | 74.25 MHz | 371.25 MHz | M=29.700, D=1, O0=20 (pixel), O1=4 (5x) |
| 1080p60 | 148.5 MHz | 742.5 MHz | M=29.700, D=1, O0=10 (pixel), O1=2 (5x) |

The MMCM fractional multiplier enables exact 74.25 MHz generation (M=29.700 from 50 MHz input = 1485 MHz VCO... which exceeds VCO max). Alternative approaches:

### 6.2 Practical HDMI MMCM Settings

| Resolution | f_CLKIN | M | D | O_pixel | O_ser | f_VCO | f_pixel | f_ser | Exact? |
|------------|:-------:|--:|--:|:-------:|:-----:|:-----:|:-------:|:-----:|:------:|
| 720p | 50 MHz | 14.850 | 1 | 10 | 2 | 742.5 | 74.25 | 371.25 | Yes |
| 720p | 100 MHz | 7.425 | 1 | 10 | 2 | 742.5 | 74.25 | 371.25 | Yes |
| 1080p | 50 MHz | 14.850 | 1 | 5 | 1 | 742.5 | 148.5 | 742.5 | Yes |

**Note**: f_VCO = 742.5 MHz is within the 600-1200 MHz range. The MMCM fractional multiplier (M=14.850) makes exact HDMI pixel clocks trivial on Xilinx, whereas Gowin required a separate PLL at 126 MHz with a CLKDIV to get 25.2 MHz (720p only, not exact CEA-861 timing).

### 6.3 HDMI Clock Comparison (Gowin vs Xilinx)

| Aspect | Gowin (Current) | Xilinx (Planned) |
|--------|:---------------:|:----------------:|
| Pixel clock | 25.2 MHz (480p-equivalent) | 74.25 MHz (720p) or 148.5 MHz (1080p) |
| Serializer | 126 MHz (5x pixel) | 371.25 or 742.5 MHz |
| PLL consumed | 1 of 2 (50% of total) | 1 of 6 (17% of total) |
| Resolution | 720x480 equivalent | True 720p or 1080p |
| Exact CEA timing | No (25.2 vs 25.175 MHz) | Yes (fractional MMCM) |

## 7. CDC Between Clock Domains

### 7.1 Architecture Options

Two approaches for connecting the AXI bus domain to the ATOMiK core:

| Approach | CDC Required | Complexity | Recommended For |
|----------|:------------:|:----------:|-----------------|
| **Same clock** (ATOMiK on FCLK) | No | Minimal | Phase 1 bringup |
| **Separate MMCM** (ATOMiK faster) | Yes | Moderate | Production (higher throughput) |

### 7.2 Same-Clock Approach (Phase 1 Recommended)

Run ATOMiK directly on the AXI bus clock (FCLK_CLK0, e.g., 100 MHz):

- No CDC bridge needed
- No MMCM consumed
- ATOMiK at 100 MHz is already faster than Gowin production (81 MHz)
- Simplest integration path: AXI4-Lite slave registers drive ATOMiK combinationally

```
PS (ARM) --> AXI GP0 --> AXI Interconnect --> AXI4-Lite Slave --> ATOMiK Core
                         (FCLK_CLK0)         (FCLK_CLK0)        (FCLK_CLK0)
```

### 7.3 Separate-Clock Approach (Production)

Use an MMCM to generate a faster ATOMiK clock (e.g., 200 MHz):

- Toggle-handshake CDC bridge between AXI domain and ATOMiK domain
- Same CDC architecture as the v3 Gowin design
- MMCM output drives ATOMiK core via BUFG
- False-path constraints between domains (handshake handles synchronization)

```
PS (ARM) --> AXI GP0 --> AXI4-Lite Slave --> CDC Bridge --> ATOMiK Core
             (FCLK)      (FCLK)             (FCLK|clk_a)   (clk_atomik)
                                                             (MMCM output)
```

### 7.4 CDC Bridge Port Map (~estimate)

The toggle-handshake CDC bridge from the Gowin design can be reused directly:

| Signal | Width | AXI Domain | ATOMiK Domain | Direction |
|--------|:-----:|:----------:|:-------------:|:---------:|
| req_toggle | 1 | Source | Synchronized | AXI -> ATOMiK |
| ack_toggle | 1 | Synchronized | Source | ATOMiK -> AXI |
| cmd_data | ~96 | Registered | Sampled | AXI -> ATOMiK |
| rsp_data | ~64 | Sampled | Registered | ATOMiK -> AXI |

~Resource cost: ~30 LUT6, ~40 FF (same toggle-handshake as Gowin, fewer LUT6 due to wider LUTs).

## 8. XDC Timing Constraint Templates

### 8.1 PS FCLK Clocks

PS-generated clocks are typically auto-constrained by Vivado when the Zynq PS block is configured. Manual constraint is usually not needed but can be added for clarity:

```tcl
# PS FCLK_CLK0 — usually auto-generated by Vivado
# Uncomment only if Vivado does not auto-constrain:
# create_clock -period 10.000 -name clk_fclk0 [get_pins PS7_i/FCLK_CLK0]
```

### 8.2 ATOMiK MMCM Output (if using separate clock)

```tcl
# ATOMiK MMCM-generated clock
# Vivado usually auto-derives generated clocks from MMCM outputs.
# Manual constraint for reference:
create_generated_clock -name clk_atomik \
    -source [get_pins u_mmcm/CLKIN1] \
    -multiply_by 20 -divide_by 10 \
    [get_pins u_mmcm/CLKOUT0]
```

### 8.3 CDC False Paths (if using separate ATOMiK clock)

```tcl
# Toggle-handshake CDC — paths are synchronized by design.
# False-path both directions to prevent the timing analyzer from
# trying to close timing across domains.
set_false_path -from [get_clocks clk_fclk0] -to [get_clocks clk_atomik]
set_false_path -from [get_clocks clk_atomik] -to [get_clocks clk_fclk0]
```

### 8.4 HDMI Clocks (if PL-driven)

```tcl
# HDMI pixel clock and serializer clock from dedicated MMCM
create_generated_clock -name clk_pixel \
    -source [get_pins u_hdmi_mmcm/CLKIN1] \
    -multiply_by 14850 -divide_by 10000 \
    [get_pins u_hdmi_mmcm/CLKOUT0]

create_generated_clock -name clk_serial \
    -source [get_pins u_hdmi_mmcm/CLKIN1] \
    -multiply_by 14850 -divide_by 2000 \
    [get_pins u_hdmi_mmcm/CLKOUT1]

# HDMI is async to AXI and ATOMiK domains
set_false_path -from [get_clocks clk_fclk0] -to [get_clocks clk_pixel]
set_false_path -from [get_clocks clk_pixel] -to [get_clocks clk_fclk0]
```

### 9.2 Instantiation Template (MMCME2_BASE, Simplified)

For most ATOMiK use cases, MMCME2_BASE (no DRP, no phase shift) is sufficient:

```verilog
MMCME2_BASE #(
    .BANDWIDTH          ("OPTIMIZED"),   // "HIGH", "LOW", "OPTIMIZED"
    .CLKFBOUT_MULT_F    (20.0),          // M: feedback multiplier (2.0-64.0)
    .CLKFBOUT_PHASE     (0.0),           // Feedback phase offset
    .CLKIN1_PERIOD       (20.0),          // Input period in ns (50 MHz = 20.0)
    // Output 0: ATOMiK clock
    .CLKOUT0_DIVIDE_F   (5.0),           // O0: fractional divide (1.0-128.0)
    .CLKOUT0_DUTY_CYCLE (0.5),
    .CLKOUT0_PHASE      (0.0),
    // Output 1: available for other use
    .CLKOUT1_DIVIDE     (10),            // O1: integer divide (1-128)
    .CLKOUT1_DUTY_CYCLE (0.5),
    .CLKOUT1_PHASE      (0.0),
    .DIVCLK_DIVIDE      (1),             // D: input divider (1-106)
    .REF_JITTER1        (0.010),
    .STARTUP_WAIT       ("FALSE")
) u_mmcm (
    .CLKIN1     (clk_50mhz),       // 50 MHz from PS FCLK
    .CLKFBIN    (clk_fb),          // Feedback (connect to CLKFBOUT)
    .RST        (mmcm_reset),      // Active-HIGH reset
    .PWRDWN     (1'b0),            // Not powered down
    .CLKOUT0    (clk_atomik_raw),  // 200 MHz (50 * 20 / 1 / 5)
    .CLKOUT1    (clk_aux_raw),     // 100 MHz (50 * 20 / 1 / 10)
    .CLKOUT2    (),
    .CLKOUT3    (),
    .CLKOUT4    (),
    .CLKOUT5    (),
    .CLKOUT6    (),
    .CLKFBOUT   (clk_fb),          // Feedback output -> CLKFBIN
    .CLKFBOUTB  (),
    .LOCKED     (mmcm_locked)      // Lock indicator
);

// Global clock buffers for fabric distribution
BUFG u_bufg_atomik (.I(clk_atomik_raw), .O(clk_atomik));
BUFG u_bufg_aux    (.I(clk_aux_raw),    .O(clk_aux));
```

### 9.3 Instantiation Template (PLL, Integer Only)

```verilog
PLLE2_BASE #(
    .BANDWIDTH          ("OPTIMIZED"),
    .CLKFBOUT_MULT      (20),            // M: integer only (2-64)
    .CLKFBOUT_PHASE     (0.0),
    .CLKIN1_PERIOD       (20.0),          // 50 MHz input
    .CLKOUT0_DIVIDE     (5),             // 200 MHz
    .CLKOUT0_DUTY_CYCLE (0.5),
    .CLKOUT0_PHASE      (0.0),
    .DIVCLK_DIVIDE      (1),             // D: integer (1-56)
    .REF_JITTER1        (0.010),
    .STARTUP_WAIT       ("FALSE")
) u_pll (
    .CLKIN1     (clk_50mhz),
    .CLKFBIN    (clk_fb),
    .RST        (pll_reset),
    .PWRDWN     (1'b0),
    .CLKOUT0    (clk_out_raw),
    .CLKFBOUT   (clk_fb),
    .LOCKED     (pll_locked)
);

BUFG u_bufg (.I(clk_out_raw), .O(clk_out));
```

### 9.4 Key Differences from Gowin Instantiation

| Aspect | Gowin rPLL | Xilinx MMCM/PLL |
|--------|-----------|-----------------|
| Configuration | `defparam` blocks | Generic parameters (`#(...)`) |
| Feedback | Internal (`CLKFB_SEL = "internal"`) | External loopback (CLKFBOUT -> CLKFBIN) |
| Output buffering | Implicit (PLL drives routing directly) | Explicit (must instantiate BUFG) |
| Reset polarity | Active-HIGH (RESET) | Active-HIGH (RST) |
| Lock signal | LOCK | LOCKED |
| Divider encoding | IDIV_SEL = value - 1 | DIVCLK_DIVIDE = actual value |

## 10. Troubleshooting

### MMCM Won't Lock

1. **Check VCO frequency**: f_VCO = f_CLKIN * M / D must be within 600-1200 MHz
2. **Verify input clock**: Ensure PS FCLK is running and at expected frequency
3. **Check reset**: RST is active-HIGH. Assert for at least 10 CLKIN cycles, then deassert
4. **Check feedback**: CLKFBOUT must be connected to CLKFBIN (external feedback loop)
5. **Missing BUFG**: CLKFBOUT should go through BUFG if feedback path has significant skew

### Frequency Incorrect

1. **Verify parameters**: M, D, O use actual values (not value-1 like Gowin IDIV_SEL)
2. **Check CLKFBIN**: If BUFG is on feedback path, it adds skew (MMCM compensates automatically)
3. **Fractional precision**: MMCM fractional divide has 0.125 step resolution (3 fractional bits)
4. **Wrong CLKIN1_PERIOD**: This parameter is in nanoseconds, not MHz. 50 MHz = 20.0 ns

### Timing Closure

1. **Check LOCKED before using clock**: Gate logic enable on MMCM LOCKED signal
2. **Add false paths for CDC**: See Section 8.3
3. **Use BUFH instead of BUFG**: If clock only serves one region, BUFH has lower insertion delay
4. **Pipeline long paths**: ATOMiK XOR tree may need pipeline stages at higher frequencies (~250+ MHz)

### Vivado-Specific Notes

- Vivado auto-derives generated clock constraints for MMCM/PLL outputs. Manual `create_generated_clock` is optional but recommended for clarity.
- The Clocking Wizard IP can configure MMCM/PLL via GUI and generates a wrapper module. For ATOMiK, direct primitive instantiation is preferred for full control.
- DRC rule PDRC-34 warns if CLKFBIN is not connected. Always connect the feedback loop.
